# Исправления по результатам ревью

Здесь перечислены исправленные дефекты и условия безопасного обновления приложения. Продуктовые идеи вынесены в [отдельный список предложений](improvements.md).

## Целостность данных

| Дефект | Новое поведение |
| --- | --- |
| Потеря ответа повторно увеличивала количество | У операции постоянный `X-Mutation-Id`. SQLite сохраняет результат вместе с изменением; повторная доставка возвращает прежний результат. Другой запрос с тем же id отклоняется. |
| Две вкладки удаляли неподтверждённый хвост очереди | Каждое действие хранится отдельной записью. Удаляется только подтверждённый id. Web Locks последовательно запускает отправителей; серверная дедупликация защищает повторные доставки. |
| Действия аккаунта A отправлялись с токеном B | Очередь, снимки, каталог и undo привязаны к неизменяемому id пользователя. Смена сессии останавливает старую отправку и не позволяет принять старый обновлённый токен. |
| Быстрые онлайн-нажатия приходили в обратном порядке | Онлайн и офлайн используют общую долговечную очередь с последовательной отправкой. |
| Запоздавший GET стирал уже добавленное на экране | Проверяются поколения чтения, локальные изменения, состояние очереди и сессия. Старый ответ не заменяет новое состояние. |
| Очередь оставалась неподвижной после временного сбоя | Повтор с увеличением интервала, учёт Retry-After, повтор при reconnect, focus, pageshow и возвращении сети; доступна ручная попытка. Сетевые запросы ограничены по времени. |
| Отклонённые изменения исчезали | Их намерение сохраняется в разделе «Синхронизация» с объяснением конфликта или отказа. |
| Офлайн-очистка захватывала позже купленные товары | Очистка отправляет конкретные id, выбранные пользователем. Безвозвратная очистка также ограничена показанными позициями и требует подтверждения в интерфейсе. |
| После офлайн-запуска исчезал каталог списков | Каталог сохраняется для аккаунта, сетевые ошибки оставляют предыдущие данные. Ошибка и загрузка показаны отдельно. |
| Вкладка, открытая из другой, пропускала изменения | Идентификатор создаётся для каждого экземпляра страницы; собственные события также проходят безопасное обновление. |

## Сессии и доступ

| Дефект | Новое поведение |
| --- | --- |
| Токен удалённого аккаунта давал доступ после повторной регистрации логина | JWT содержит неизменяемый `sub`; каждый запрос проверяет существование пользователя и версию сессии. Совпадение логина не восстанавливает прежнюю идентичность. |
| Смена пароля сохраняла старые токены | Версия сессии увеличивается, старые токены и соединения отзываются. Текущий браузер получает новый токен. |
| Ошибка текущего пароля разлогинивала пользователя | Это отдельная ошибка формы с кодом `WRONG_PASSWORD`; сессия сохраняется. |
| Отозванный участник оставался в комнате realtime | Соединение исключается из комнаты, клиент получает отзыв доступа, состав присутствующих обновляется. |
| Названия и состав списков не обновлялись у участников | Каталог получает отдельные события на создание, переименование, присоединение, выход и удаление. |
| Копия ссылки позволяла вернуться после удаления участника, а текст обещал полный запрет | Сообщение прямо объясняет, что старая ссылка позволяет присоединиться снова. Полное закрытие приглашения требует смены ссылки. |
| Уязвимые зависимости | Lockfile обновлён; проверка production-зависимостей входит в проверку кандидата. |

## Ввод и интерфейс

| Дефект | Новое поведение |
| --- | --- |
| Редактор закрывался после отклонённого сохранения | Ожидает результат, сохраняет черновик и показывает ошибку. При временной недоступности действие остаётся в долговечной очереди и видно как ожидающее отправки. |
| Ручное добавление теряло текст после отказа | Поле очищается после успешного принятия действия; отклонённый ввод остаётся. Импорт сохраняет выбор оставшихся позиций после частичного выполнения. |
| «Вернуть» отменяло более позднее чужое по смыслу действие | У уведомления сохранён id конкретной записи undo. Общая кнопка отмены по-прежнему работает с последним действием. |
| Ошибка undo считалась успехом | Отказ сохраняет запись для повторной попытки; временная недоступность сохраняет саму операцию в очереди. Редактирование, удаление и обратный перенос проверяют ожидаемое состояние. |
| Повторное добавление купленного игнорировало новое количество | Возврат и новое количество сохраняются одной операцией, с возможностью отмены. |
| «2 молока» в поле и голосом давали разные результаты | Ручной ввод использует общий разбор количества и показывает предварительный результат. Несколько позиций открывают импорт для просмотра. |
| «Удали молоко» выбирало первый из нескольких вариантов | Команда удаления или отметки требует выбора при неоднозначности; отмена выбора ничего не меняет. |
| Свайп не начинался на названии | Название участвует в жесте; синтетический click после свайпа подавляется. Остальные кнопки сохраняют свои жесты. |
| На 320 px название сжималось до нескольких букв | Заголовок и действия могут занимать отдельные строки; количество и меню не вытесняют название. Пустая заметка не занимает отдельную строку. |
| Первый вход перекрывался длинной справкой | Показана короткая подсказка рядом со списком; полная справка доступна по кнопке. |
| Пустое состояние маскировало загрузку или ошибку | Список, каталог, удалённое и доступ различают загрузку, ошибку и пустоту; доступен повтор. |
| Ошибки микрофона скрывались или приводили к бесконечному перезапуску | Показано подключение, запуск ограничен по времени, сетевые и аппаратные ошибки объясняются; пустые перезапуски ограничены. |
| Недостаточный контраст второстепенного текста | Светлая тема использует более тёмный цвет. Checkbox сообщает своё состояние; редакторы имеют подпись с названием позиции. |
| Модальное окно допускало работу с фоном | Фоновая прокрутка блокируется; соседние ветки интерфейса становятся inert на время открытого окна. Уведомления доступны с клавиатуры. |

## Уведомления и эксплуатация

Устройство может подписаться на несколько списков. Отключение одного списка сохраняет остальные подписки. Ожидание регистрации service worker больше не оставляет переключатель навсегда скрытым. Уведомление подавляется только при открытом и активном соответствующем списке.

`GET /api/health` проверяет доступность SQLite. Dockerfile содержит healthcheck. Скрипт выпуска собирает кандидат, делает снимок существующей базы и обновляет только `web`; остановленный контейнер больше не считается доказательством отсутствия данных.

## Проверки

20 октября 2026 года в изолированной копии прошли сборка, линтер, 229 тестов, полный API smoke и 18 браузерных сценариев. Полный `npm audit`, включая зависимости разработки, сообщил 0 известных уязвимостей. На 320 px измеренная ширина первого длинного названия выросла с 26 до 175 px; горизонтального переполнения нет.

Запускать на `big-one` в отдельной копии исходников, без `.env` и production-данных:

```bash
npm ci
npm run lint
npm test
npm run build
npm run smoke
npx playwright install chromium
npm run test:browser
npm audit --omit=dev
```

API smoke поднимает сервер с отдельной SQLite и проверяет миграции, права, идемпотентность, ограниченную очистку и отзыв токенов. Браузерные регрессии поднимают свой сервер на loopback, создают синтетические аккаунты, проверяют Chromium на 320/390 px, PWA без сети, потерю ответа, две вкладки, очередь, редактор, отмену, голосовую неоднозначность и подписки. Скриншоты и JSON-результаты сохраняются в `BROWSER_ARTIFACTS` либо во временный каталог. Тестовая база удаляется, сервер останавливается.

Голос в автоматической проверке подаётся через имитацию SpeechRecognition. Это проверяет применение команды, но не качество распознавания реального микрофона. Доставка Web Push на телефон, Safari, VoiceOver и TalkBack требуют отдельных проверок на своих устройствах.

## Условия выпуска и восстановления

Миграция `009-sessions-mutations-push.sql` добавляет версии сессий, таблицу результатов операций и ключ подписки из устройства и списка. Товары и их поля миграция не переписывает.

После обновления пользователям с прежними JWT потребуется войти заново: у старых токенов нет неизменяемого id и версии сессии. Сохранение их действия оставило бы найденную уязвимость.

Старая очередь `offline_queue_v2` не содержит достоверной привязки к аккаунту. Она сохраняется для явного просмотра в «Синхронизации» и не отправляется автоматически от имени следующего вошедшего пользователя. Такие действия нужно проверить и при необходимости повторить в нужном списке. Новая очередь сохраняется при выходе; снимки с ожидающими действиями остаются привязанными к прежнему аккаунту.

Перед выпуском сохранить предрелизный образ и снимок SQLite. Проверить миграцию на отдельной копии снимка. При необходимости отката нельзя запускать старую реализацию push поверх новой схемы: её `ON CONFLICT(endpoint)` несовместим с составным ключом. Откат включает согласованное восстановление базы и образа; восстановление старого снимка потеряет более поздние изменения, поэтому требует отдельного решения владельца.

Непривилегированный контейнер, лимиты ресурсов, полноценный журнал изменений и крупная перестройка главного экрана остаются в списке предложений. Текущий выпуск их не активирует.
